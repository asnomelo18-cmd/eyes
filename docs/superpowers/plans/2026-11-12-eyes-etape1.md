# Eyes — Étape 1 : plan de construction

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Objectif :** une app Android qui partage caméra + micro vers une app Windows qui affiche un ou plusieurs téléphones en direct, sur le même Wi-Fi.

**Architecture :** le téléphone annonce un service mDNS `_eyes._tcp` et héberge un serveur WebSocket sécurisé (wss, certificat auto-signé). Le PC le découvre, se jumelle avec un code à 6 chiffres (il reçoit un jeton et épingle l'empreinte du certificat), puis demande un flux WebRTC : le téléphone fait l'offre, le PC répond en réception seule. Pas de serveur tiers.

**Technologies :** Android : Kotlin, Jetpack Compose, Ktor (CIO + WebSockets), `io.getstream:stream-webrtc-android`, BouncyCastle, DataStore, kotlinx.serialization. PC : Python 3.13, PySide6, qasync, aiortc, websockets, zeroconf, sounddevice, cryptography, pytest.

**Spec :** `docs/superpowers/specs/2026-11-11-eyes-etape1-design.md`

## Contraintes globales

- PC : Windows 10, Python 3.13. Téléphones : Android, `minSdk 26`, `targetSdk 35`, plusieurs marques.
- Service mDNS : type `_eyes._tcp`, nom = nom de l'appareil, TXT `id=<phoneId>`, `v=1`.
- Version de protocole : `1`. Messages JSON sur WebSocket sécurisé (wss), clé `type` obligatoire.
- Code de jumelage : 6 chiffres, valable **2 minutes**, **5 essais faux** max, accepté seulement si l'écran « Jumeler un PC » est ouvert.
- Jeton : 256 bits aléatoires (encodé base64url), comparé en temps constant.
- Le PC épingle l'empreinte SHA-256 du certificat du téléphone au jumelage et refuse toute autre empreinte ensuite.
- Un seul PC à la fois par téléphone (`error` `busy` pour le second). Un PC peut voir plusieurs téléphones ; avertissement au-delà de 4.
- Vidéo 1280×720 @ 30 i/s visés ; audio Opus mono. ICE : candidats hôte uniquement, pas de STUN/TURN.
- Les SDP sont envoyées **complètes** (après la fin de la collecte ICE) : le message `ice` est réservé, non utilisé à l'étape 1 (choix de construction : aiortc ne fait pas de trickle ICE).
- Stockage PC : `%APPDATA%\Eyes\pairings.json`.
- Toutes les chaînes visibles par l'utilisateur sont en français.
- Notification visible sur le téléphone en permanence pendant « Prêt à partager » et pendant tout partage ; jamais désactivable.

## Protocole (référence partagée par les deux apps)

| `type` | Sens | Champs |
|---|---|---|
| `pair` | PC → tél | `code: str`, `pcId: str`, `pcName: str`, `v: int` |
| `paired` | tél → PC | `token: str`, `phoneId: str`, `phoneName: str` |
| `hello` | PC → tél | `pcId: str`, `token: str`, `v: int` |
| `welcome` | tél → PC | `phoneId: str`, `phoneName: str` |
| `denied` | tél → PC | `reason: "unknown" \| "revoked" \| "version" \| "bad_code" \| "code_expired" \| "not_pairing"` puis fermeture |
| `start` | PC → tél | `video: bool`, `audio: bool`, `camera: "back" \| "front"` |
| `offer` / `answer` | tél → PC / PC → tél | `sdp: str` |
| `set` | PC → tél | `video?: bool`, `audio?: bool`, `camera?: "back" \| "front"` |
| `stop` | PC → tél | — |
| `error` | tél → PC | `code: "busy" \| "camera_busy" \| "permission_missing" \| "bad_message"` |

`revoked` : le `pcId` a été retiré sur le téléphone. `unknown` : `pcId` jamais vu ou jeton faux.

## Points d'attention de la relecture

1. **Le téléphone change d'adresse IP (DHCP) ou mDNS est bloqué par la box** → le PC doit tenter la dernière IP connue puis afficher « Téléphone introuvable sur le Wi-Fi » et non planter. Test : Tâche 3.
2. **Le Wi-Fi coupe en pleine vue** → la tuile affiche « Connexion perdue » et un bouton « Reconnecter », les autres tuiles continuent. Test : Tâche 5.
3. **La caméra est déjà utilisée par une autre app sur le téléphone** → `error camera_busy`, message clair sur le PC. Tests : Tâches 10 et 11.
4. **Un message JSON invalide ou un type inconnu arrive** → réponse `error bad_message`, la connexion n'est pas tuée et l'app ne plante pas. Tests : Tâches 1 et 10.
5. **Le PC retiré sur le téléphone pendant une vue en cours** → le partage s'arrête immédiatement et le PC reçoit `denied revoked`. Test : Tâche 10.
